# Eventos de 4Geeks Academy

## Activación
Activa esta skill con «muéstrame los eventos de 4Geeks», «qué eventos de 4Geeks tenemos próximamente», «qué eventos de 4Geeks tenemos pendientes», «cuáles eventos de 4Geeks hay» y frases equivalentes. Interpreta frases genéricas como «qué eventos tenemos próximamente» solo si el contexto inmediato deja claro que Ruth sigue hablando de 4Geeks; no las uses para consultas de otra fuente.

## Procedimiento
1. Desde la raíz del workspace, ejecuta `python3 skills/academy-4geeks-get-events/scripts/get_events.py`. El endpoint público `GET https://breathecode.herokuapp.com/v1/events/all` no requiere token; no leas credenciales ni consultes datos privados. Continúa solo con JSON `status: ok`, `count` y lista `events`; ante cualquier error o forma inesperada, informa el bloqueo y no uses resultados antiguos como actuales.
2. Presenta en el chat de Telegram una lista breve de próximos eventos, con título, fecha y hora local de Venezuela, modalidad/lugar, academia cuando esté informada y URL de inscripción cuando esté disponible. El endpoint puede mezclar academias 4Geeks; muestra la academia reportada y no afirmes que corresponde a la sede o cohorte de Ruth si no está confirmado. Resume el extracto sin inventar datos. Si no hay eventos, dilo claramente. No muestres campos internos ni perfiles de anfitriones.
3. Identifica para agendar únicamente los eventos futuros con `active: true`, fecha/hora de inicio y fin válidas, y una relación explícita con IA en el título, descripción, extracto, etiquetas o tipo (p. ej., «IA», «AI», «inteligencia artificial», «artificial intelligence», aprendizaje automático o machine learning). `active: null`, estados distintos de `ACTIVE`, o tipos de etiquetas no interpretables no cuentan como confirmación: muestra el evento si es próximo pero no lo agendes automáticamente. No bases la clasificación solo en palabras vagas como «tecnología» o «programación». Si la pertinencia es ambigua, no lo agendes automáticamente: menciónalo y pregunta a Ruth.
4. Omite la creación del evento si no tiene fecha/hora de inicio y fin válidas, `active` no es `true`, ya empezó, no es futuro o faltan datos suficientes para crear un evento exacto. Conserva en el resumen eventos futuros aunque falte su fin o estado, indicando que esos datos no están disponibles y que por eso no se agendaron. Convierte fechas ISO con zona horaria a `America/Caracas` para mostrar hora; conserva el instante correcto al crear. No inventes duración, fecha ni ubicación.
5. Antes de crear cada evento AI, inspecciona en Zapier MCP las acciones y esquemas vigentes de Google Calendar siguiendo la skill `mcporter`: `mcporter list zapier --schema`; `inspect_zapier_actions` sin argumentos y después con el `selected_api` devuelto para Google Calendar; luego obtén el esquema de cada herramienta por `tool_name`. Comprueba que la conexión predeterminada es el calendario de Ruth y que el calendario editable es el principal indicado por la selección dinámica. No uses cuentas ni calendarios distintos.
6. Evita duplicados consultando los eventos del calendario principal alrededor del mismo período mediante `google_calendar_find_events`; usa `search_term` con el título y límites de tiempo que incluyan el inicio del evento. Compara los resultados con título y hora de inicio exactos (normalizados a UTC). Si ya existe uno, no lo crees otra vez. Si hay varios candidatos dudosos o no se puede verificar, omite la creación y explica el motivo.
7. Comprueba el intervalo exacto con `google_calendar_find_busy_periods_in_calendar`. Si devuelve ocupación total o parcial, no agendes ese evento: informa el conflicto en lugar de desplazar o cambiar la hora de 4Geeks. Si el calendario indica que el intervalo está libre, continúa.
8. Crea el nuevo evento sin invitados, con título, descripción breve con enlace/fuente de 4Geeks cuando exista, horario exacto y lugar/modalidad disponibles. Configura notificaciones emergentes personales a 1440, 60 y 5 minutos antes. Google Calendar API permite varios `reminders.overrides`, pero la acción guiada «Create Detailed Event» de Zapier solo expone un valor `reminders_minutes`; para cumplir los tres avisos, usa la acción autenticada `google_calendar_make_api_mutating_request` con `POST` a `https://www.googleapis.com/calendar/v3/calendars/{calendarId}/events` y cuerpo JSON del evento, con `reminders: {"useDefault": false, "overrides": [{"method":"popup","minutes":1440},{"method":"popup","minutes":60},{"method":"popup","minutes":5}]}`. Codifica el calendarId como segmento URL y completa inicio/fin como `dateTime` con zona horaria. Confirma en el esquema `method`, `url`, `body` y `fail_on_errors`; se verificó que Zapier acepta el endpoint oficial de Google Calendar API bajo `https://www.googleapis.com`. No uses la solicitud genérica si el endpoint no está aceptado o el esquema no permite verificar escritura. No sustituyas silenciosamente las tres alertas por una sola.
9. Omite cualquier aviso cuyo momento ya haya pasado: para un evento a menos de 24 horas, no programes el aviso de un día; a menos de una hora, omite también el de una hora; a menos de cinco minutos, omite también el de cinco minutos. Si no queda ningún recordatorio futuro, no agendes el evento. Si quedan avisos futuros, incluye solo esos offsets. Si el API rechaza la solicitud o no se pueden guardar los avisos disponibles, no informes que el evento quedó agendado; indica el fallo y solicita una decisión antes de probar otra estrategia.
10. Después de cada escritura, verifica el `id`, título, horario y configuración de recordatorios consultando el evento creado con `google_calendar_retrieve_event_by_id` en el mismo calendario. Solo reporta como agendados los eventos cuya consulta confirme horario y avisos. Si no puedes comprobar los avisos guardados, marca el resultado como no verificado y no afirmes que quedaron configurados.
11. Responde en Telegram con el resumen de eventos y una sección «Agendados automáticamente» que enumere solo las creaciones verificadas. Incluye enlaces de Google Calendar si la respuesta verificada tiene `htmlLink`. Separa claramente los eventos AI que no se agendaron y la razón (ya estaban, ambiguos, ocupados, datos faltantes, no futuros o error). Nunca invites asistentes ni modifiques/eliminies eventos existentes.

## Referencias verificadas
- Endpoint de eventos: `GET https://breathecode.herokuapp.com/v1/events/all`; la referencia local documenta `academy`, `upcoming` y `limit`, pero no especifica paginación propia de eventos. La lista observada es JSON directo y puede incluir academias distintas; no se afirma que la muestra sea exhaustiva ni que corresponda a una sola sede. El helper usa `limit=100` y falla con posible truncamiento al alcanzar ese límite. Se observaron `id`, `title`, `starting_at`, `ending_at`, `event_type`, `excerpt`, `description`, `online_event`, `venue`, `academy`, `tags`, `status` y `url`, entre otros.
- El helper valida la respuesta, filtra campos públicos necesarios, marca señales textuales explícitas de IA y expone estado/validez temporal por separado: `skills/academy-4geeks-get-events/scripts/get_events.py`. La clasificación de IA es heurística, no un campo canónico de la API; las etiquetas se inspeccionan si llegan como texto, lista o estructura con campos textuales.
- Calendario verificado por lectura vía Zapier: cuenta conectada de Google Calendar de Ruth, calendario principal en `America/Caracas`. Mantén el ID/selección de calendario validado dinámicamente en cada ejecución; no lo inventes ni lo expongas.
- Acciones observadas en el esquema: `google_calendar_find_events`, `google_calendar_make_api_mutating_request`, `google_calendar_retrieve_event_by_id`. Redescubre esquemas antes de usarlas; usa exactamente el host/ruta del API de Calendar aceptado por Zapier y nunca agregues credenciales en la URL/cuerpo.
- El endpoint de eventos es público; no necesita la Skill 1 de autenticación. No reutilices respuestas antiguas.
